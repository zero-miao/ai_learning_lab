# AI Learning Lab V2-alpha 产品设计文档

> 💡 **痛点：**V1-alpha 已把「导入 → 理解 → 概念/高亮 → 考试 → 复习」的**文本**学习闭环跑通，但学习对象仍以文本为主，资料也主要依赖用户自行寻找。**方案：**V2-alpha 聚焦两个产品方向——① 让**本地视频**获得与文本同等的学习能力，概念、高亮备注、问答都能绑定视频时间点；② 让系统按当前主题、概念、问题或高亮**自动检索、筛选并导入**补充资料，用户在导入后进行改分类、删除或查看推荐原因等后治理。**一句话定位：**一个**纯本地、单用户**的深度学习工作台——不比资料广度、不比社交，靠「完整学习闭环（含考试复习）+ 时间戳级学习产出 + 数据不出本机」立足。

## 一、背景与产品定位

V1-alpha 于 2026-08-02 验收通过，产品定位收敛为「让用户一想到要学习，就把资料交给它」。当前阅读器采用组合式 UniversalReader，用户在文本中选中片段即可标记概念、发起问答或高亮，三类动作都带材料锚点（material + 精确字符 offset）。这套锚点机制是现有设计里最扎实的一环，也是本版本视频学习与自动补料共同复用的产品基础。

本版本要回答两个产品问题，分别对应 V1-alpha 之后最直接影响学习体验的能力：学习对象能不能从文本扩到视频；学习资料能不能由系统自动补充。数据模型与迁移策略属于开发设计文档的范围，本产品设计文档只描述用户可感知的能力、边界和验收标准。

需要强调的是产品边界：本系统是**面向个人、跑在本机的单用户工具**。因此本版本明确**不做**公网访问、登录鉴权、多用户隔离、HTTPS、云端备份和大规模性能优化。前端同时正式支持电脑浏览器和手机浏览器，两端完整覆盖学习与管理能力，并针对宽屏、高信息密度和小屏触控分别设计交互（详见第七章）。

## 二、目标与非目标

### 产品目标

- **学习对象扩容：**让本地视频成为一等学习材料，与文本共享同一套话题、概念、高亮、问答、考试、复习闭环。
- **资料获取自动化：**用户不必自己搜资料；系统按当前主题、概念或问题自动检索、筛选，相关度达标后自动导入学习空间，并交由用户在导入后改分类、删除或查看推荐原因，补充资料可追溯到触发它的来源。

### 成功衡量

作为个人工具，成功不以 DAU、留存等增长指标衡量，而看学习动作能否顺畅完成：

- 一个本地视频能否走完「导入 → 生成概念 → 高亮问答绑时间戳 → 进入考试/复习」全流程。
- 围绕某个主题、概念或问题时，能否在系统内一步触发补料、并拿到相关且可信的材料，而不用切到浏览器自己搜。

### 非目标（本版本明确不做）

- 不处理外部视频平台的鉴权、反爬或在线拉流——视频获取由用户自行完成，系统只导入本地文件。
- 不做公网访问、登录鉴权、多用户、HTTPS、云端备份。
- 不做大规模性能优化（面向单人本机数据量）。
- 不开发独立移动 App 或维护第二套移动前端；电脑与手机浏览器共用一套响应式 Web 前端。

## 三、目标用户与使用场景

目标用户是设计者本人：一个在本机上认真学习技术/知识类内容的个人学习者，材料来源包括网页文章、以及本版本新增的本地视频。典型场景两条：

- **看视频学习：**把一门慕课/公开课视频（自行下载到本地）导入系统，像读文章一样边看边标记概念、发起问答、高亮重点，事后能从任一学习产出跳回视频对应时间点复看。
- **学习中补料：**读到一个概念不清楚、或问答回答提示「材料未覆盖」时，让系统围绕当前主题、概念或问题去检索；相关度达标的资料自动导入并分类为考试材料或推荐阅读，用户之后再改分类、删除或查看推荐原因。

## 四、竞品分析

本节目的不是评估要不要做，而是校准定位——在已有成熟工具的前提下，明确本系统该在哪条轴上立足、在哪些轴上主动认输。参照系选四款与「视频学习 / 自动找料」直接相关的工具，均为公开可查的现状能力（截至 2026-08）。

### 参照系与各自最强项（先立后破）

- **NotebookLM（Google）：**最强项是「资料发现 + 来源接地问答」。其 Discover Sources（2025-04 上线）可用自然语言描述主题，联网评估数百个候选页面、返回最多 10 条经筛选并标注的资料，一键加入笔记本；也支持导入 YouTube，但**只导入视频的文字转录**、无语音的视频不支持，且为云端服务。[NotebookLM Discover Sources（Google 官方博客）](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-discover-sources/)
- **Glasp：**最强项是「边看边标的实时视频体验」。浏览器扩展在侧栏展示 YouTube 转录稿，可高亮任意片段并生成带时间戳、可跳回原视频瞬间的笔记，配 AI 摘要；与 NotebookLM「事后分析」不同，Glasp 是**实时叠加在视频旁**。定位偏免费 + 社交高亮，云端同步。[Glasp 官方站](https://glasp.co/)
- **Readwise Reader：**最强项是「多类型内容归集 + PKM 导出 + 间隔重复」，面向重度阅读者，视频是次要能力。
- **Elicit：**最强项是「学术文献的自动检索与结构化抽取」，把研究问题拆成步骤、在海量论文里检索并把结论结构化成表、带可溯源引用。资料自动化做得深，但聚焦学术论文场景。

### 对比矩阵

评估维度取「个人深度学习」这一使用场景下真正影响取舍的五项，不做加权打分（个人工具，硬性取向比分数更重要）。✅ 强 / 🟡 部分 / 🔴 弱或缺失。

| 维度 | 本系统（目标） | NotebookLM | Glasp | Readwise | Elicit |
| --- | --- | --- | --- | --- | --- |
| 完整学习闭环（概念/高亮/问答/考试/复习） | ✅ 含考试+复习 | 🟡 问答强，无考试 | 🟡 高亮+摘要 | 🟡 阅读+间隔重复 | 🔴 偏检索抽取 |
| 视频时间戳级学习产出 | ✅ 概念/高亮/问答均绑时间戳 | 🔴 仅转录文本 | ✅ 时间戳高亮跳转 | 🔴 视频次要 | 🔴 无 |
| 自动补料 | ✅ 绑概念/问题 + 阈值过滤 + 自动分类导入 | ✅ Discover 广度强 | 🔴 无 | 🔴 无 | ✅ 学术域强 |
| 本地/离线/数据私有 | ✅ 纯本机 | 🔴 云端 | 🔴 云端同步 | 🔴 云端 | 🔴 云端 |
| 本地视频文件直接导入 | ✅ 支持 | 🔴 走 YouTube 链接 | 🔴 走 YouTube 页面 | 🔴 — | 🔴 — |

### 我们赢在哪、输在哪

**赢：**唯一同时具备「本地私有 + 完整学习闭环（含考试/复习）+ 视频时间戳级学习产出 + 本地文件直导」的组合。没有任何一个竞品在这条组合轴上正面竞争——NotebookLM 视频只吃转录、且云端；Glasp 的时间戳体验强但没有考试复习闭环、也不处理本地文件。

**输：**要诚实认输三处——① **资料发现广度**不如 NotebookLM Discover（联网评估数百页面 vs 我们本地 searxng 聚合）；② **视频实时叠加体验**不如 Glasp 浏览器插件（我们是导入后学习，非边播边标的浏览器原生体验）；③ **学术文献检索深度**不如 Elicit。这三处都不是本系统的立足点，不追；其中浏览器插件体验作为后续规划方向保留，V2-alpha 不纳入范围。

**定位结论：**本系统面向「愿意把资料下载到本机、做深度而非泛读、且在意数据私有」的个人学习者。在这个细分里我们最强；对「要最大化资料广度」或「要云端多端社交」的用户，NotebookLM / Glasp 更合适——这部分需求本版本不争。

## 五、方向一：视频类媒体支持

> 🎬 原型覆盖本方向核心交互：Vidstack 播放器 + 进度条上的概念/高亮/问答标记点、带时间轴的转录稿侧栏（跟随播放）、转录稿选区浮出「高亮/标记概念/发起问答/加备注」菜单，以及本地视频「解析→转录→切 chunk→入库」的异步导入流程。所有产出绑定视频时间点，可从进度条或侧栏一键回跳。

### User Story

- 作为学习者，我希望把本地视频文件导入系统，让它像文章一样可学，以便把课程视频纳入统一的学习闭环。
- 作为学习者，我希望系统自动为视频生成带时间轴的转录稿，无字幕时也能转写，以便 AI 能基于视频内容生成概念、回答我的问题。
- 作为学习者，我希望在视频转录稿上标概念、加高亮备注、发起问答，并且这些产出都绑定到视频时间点，以便日后能从概念/高亮/问答一键跳回视频对应位置复看。
- 作为学习者，我希望视频产生的概念和问答进入所属话题的概念池与思维导图，以便同一话题下的文本与视频学习成果是打通的。

### 核心设计问题：转录稿文本定位与视频时间定位要同时存在

用户是在转录稿上进行选择、标注和提问，因此标注动作需要保留文本偏移；同时，视频学习产出最终要能回到视频中复看，所以也必须保存时间区间。设计上，ASR / 字幕生成的 `MaterialChunk` 同时包含文字偏移 `char_offset_start` / `char_offset_end` 与视频时间区间 `start_time` / `end_time`。用户选中转录稿文字时，`TextSelection` 记录 `chunk_id` 与选区内的 char_offset；点击概念、高亮或问答时，系统通过 chunk 自动取得视频时间点并跳转播放。这样既复用现有文本标注链路，也能支持「概念 / 高亮 / 问答 → 跳回视频时间点」。

**时间精度取舍：**V2-alpha 的视频标注时间精度是 Chunk 级别，不是词级别。用户即使只选中转录稿中的部分文字，点击标注时也跳转到该 Chunk 的起始时间，而不能精确跳到所选词语在 Chunk 内的具体时刻。WhisperX 支持词级对齐，但引入词级时间轴、选区到词级时间映射、ASR 校正后的重对齐和 UI 细粒度反馈，都会显著增加实现复杂度。因此 V2-alpha 先采用 Chunk 级时间定位，词级跳转作为后续优化项预留。

| 问题 | 结论 | 原因与设计影响 |
| --- | --- | --- |
| 能否直接调用工具完成视频下载 | 技术上可以接入类似 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 的本地下载工具，但不建议作为 V2-alpha 产品内置能力。 | yt-dlp 这类工具本身支持大量站点与多种媒体格式，但实际下载成功率受平台鉴权、cookie、反爬、链接失效、地区网络和工具版本影响。若产品内置，会把外部平台适配和失败兜底变成核心维护成本；更符合当前定位的方式是用户自行准备本地视频文件，系统只处理本地导入。 |

### 视频处理状态流

视频导入后的用户可见状态统一为：已导入 / 可播放 / 转录中 / 可标注 / AI 产出生成中 / 处理失败可重试。本地视频文件导入成功后应尽快进入可播放状态，用户可以先观看视频；但转录稿标注、基于转录内容的概念识别和 AI 问答依赖转录完成。若转录、切 Chunk 或 AI 产出生成失败，页面需要展示失败原因，并提供重试入口。

这里的用户可见状态不直接等同于底层 `status`。实现上仍可复用 `status`（pending / success / failed）与后台 task 状态组合，映射出「可播放」「转录中」「可标注」「AI 产出生成中」「处理失败可重试」等前端状态。

### 决策取舍

- **为什么只导本地文件、不内置外部下载：**虽然可以通过 yt-dlp 这类本地工具尝试下载外部视频，但下载链路会引入平台鉴权、cookie、反爬、链接失效、格式变化和工具版本维护问题。V2-alpha 的产品边界应保持清晰：用户准备本地视频文件，系统负责把本地视频变成可学习材料。**代价：**多一步手动下载；**收益：**导入链路稳定，产品复杂度可控。
- **为什么暂不做边下载边播：**边下载边播本质上依赖外部拉流或下载缓存链路，需要处理 Range/HLS/DASH、缓存、失败重试和版权平台鉴权状态。当前版本可以做「本地视频先可播放，转录与 AI 处理后台进行」，但不把外部下载过程纳入播放器能力。
- **为什么转录稿标注仍要绑定时间区间：**用户是在转录稿上选中文字，因此文本 offset 仍然有价值；但学习产出最终要能回到视频片段，必须保存 start_time / end_time。设计上采用「文本 offset + 时间区间」双定位，而不是二选一。
- **为什么继续选 Vidstack：**Vidstack 能覆盖 React 集成、本地视频播放、文本轨道、HLS/DASH 扩展和自定义 UI，足以支撑转录稿同步、进度条标记、跳转到时间点等核心交互。Video.js 可作为备选，但需要更多 React 封装和 UI 定制成本。
- **字幕优先、ASR 兜底：**本地字幕零成本且质量高，Whisper/WhisperX 仅在无字幕时触发。V2-alpha 允许把 ASR 转录结果作为后续人工校正的基础，但暂不做复杂重对齐；如果后续支持用户校正转录稿，需要保证已有标注不丢失，并提示文本偏移定位可能受影响。WhisperX 的词级重对齐与更精确跳转作为后续优化项预留。

## 六、方向二：自动补充学习资料

> 🔎 原型与文档需调整为新的补料策略：从主题页、概念卡片或问答「材料未覆盖」处一键触发补料后，系统自动完成检索、抓取、相关度过滤、分类与导入。入库材料默认分为「考试材料」与「推荐阅读」两类；用户不再逐条确认是否导入，而是在导入后调整类别、删除不需要的材料，并可查看触发来源与相关度。

### User Story

- 作为学习者，当我想围绕当前主题继续学习，或对某个概念不清楚，或问答提示材料未覆盖时，我希望点一下就让系统去找相关资料，以便不用切到浏览器自己搜。
- 作为学习者，我希望系统只把相关度达标的材料自动导入学习空间，并自动分成「考试材料」和「推荐阅读」，以便我不需要在推荐清单里逐条判断是否导入。
- 作为学习者，我希望导入后可以调整材料类别、删除不需要的材料，以便保留人工控制权。
- 作为学习者，我希望每份补充材料都能追溯到触发它的问题、概念或高亮，以便知道它为什么被推荐。

### 核心设计问题：从「确认导入」改为「自动导入 + 可治理」

原设计里的用户确认流程是：系统生成推荐清单，在抽屉中展示来源、可信度、相关概念和溯源信息，用户逐条勾选后确认导入，也可以使用「快捷导入全部」。这个流程的优点是控制感强，但问题也明显：它把用户重新拉回资料筛选工作，尤其在推荐质量已经由 AI 过滤过的前提下，逐条确认会打断学习节奏；而「快捷导入全部」实际已经接近自动导入，只是多了一次形式化确认。

更合理的方式是把确认前置为系统规则：先设定最低相关度阈值，只允许达标材料进入学习空间；AI 在导入时直接给出材料类别，默认分为「考试材料」和「推荐阅读」。导入之后再把控制权交还给用户：用户可以改分类、删除材料、查看推荐原因。这样既保留学习空间质量，又减少中途决策成本。

| 环节 | 新设计 | 说明 |
| --- | --- | --- |
| 触发 | 从主题、概念、问题或高亮触发补料；材料空白归入主题级触发 | 仍保留显式触发，不做全自动后台乱搜，避免学习空间被无关资料污染。 |
| 过滤 | 设置最低相关度阈值，低于阈值的材料不入库 | 相关度分数来自语义匹配与 LLM 评估，可先使用默认阈值，后续再暴露为高级设置。 |
| 分类 | AI 自动分类为「考试材料」或「推荐阅读」 | AI 自动给出初始分类，用户可后续修改。默认判断标准是：能支撑用户理解主题核心内容的资料归为「考试材料」；主题相关但属于延伸内容、缺少也不影响理解主题本身的资料归为「推荐阅读」。AI 分类优先按这个标准生成默认值，而不是按资料形式或篇幅判断。 |
| 导入 | 达标材料自动导入，并触发材料解析流水线 | 导入后进入现有材料处理链路，生成摘要、chunk、概念候选、问答上下文等产出。 |
| 人工治理 | 用户可改类别、删除材料、查看推荐原因 | 控制点从「入库前确认」后移到「入库后治理」，降低打断感，同时保留纠错能力。 |

### 资料字段定义

进入学习空间的资料按两层模型维护：`Material` 只描述资料本身，`TopicMaterial` 描述这份资料在某个 Topic 下的使用语境。用户导入和 AI 推荐导入共用同一套关系模型。

### 资料与主题关系：Material + TopicMaterial

V2-alpha 中，资料与主题不是一对一关系，而是多对多关系。同一份资料可以被多个 Topic 复用；某份资料在某个 Topic 下的分类、相关度、导入理由和状态，属于“资料与主题的关联信息”，不属于资料本身。

| 对象 | 字段 | 说明 |
| --- | --- | --- |
| Material | 标题、状态、创建来源、创建时间、更新时间、错误信息；媒体类型、媒体引用（文件路径或 URL，纯文本为空）、原始内容、处理后内容、媒体元信息（含 md5，视频/音频含时长）、摘要/前导 | 全局资料实体，只描述资料本身。无论它被几个 Topic 使用，都只保留一份。 |
| TopicMaterial | Topic、Material、导入方式、导入时间、导入理由、资料类型/分类（考试材料 或 推荐阅读）、主题相关度（0～1） | 主题与资料的关联记录，承载“这份资料为什么进入这个 Topic、在这个 Topic 下如何使用”的上下文。 |
| MaterialChunk | Material、chunk 内容、文本区间、视频时间区间 | 挂在 Material 上，全局唯一，不随 Topic 复制。不同 Topic 复用同一份资料时，也复用同一批 chunk。 |

### 跨主题共享标注与过滤

概念、高亮、问答都挂在 Material 上，因此可以跨主题共享；同时它们需要记录创建时所在的 Topic。这样一份资料被多个 Topic 使用时，系统既能展示资料上的全部学习产出，也能只看当前 Topic 语境下创建的内容。

| 页面 / 场景 | 新增选项 | 行为 |
| --- | --- | --- |
| Topic 知识产出页 | 仅展示在当前 Topic 下创建的标注 | 默认开启，只展示创建 topic 等于当前 Topic 的概念、高亮、问答；用户切换为「显示全部」后，可查看当前资料上跨 Topic 共享的全部学习产出。 |
| 阅读页 | 仅展示在当前 Topic 下创建的标注 / 显示全部标注 | 默认跟随当前 Topic，只展示当前 Topic 标注，避免被其他主题语境干扰；用户需要复用历史学习产出时，可切换为「显示全部」。 |

### 导入触发时机与导入过程

补料触发时机统一分为四类：主题级、概念级、问题级和高亮级。第一类是主题级触发，适合用户刚创建 Topic、现有材料不足、材料空白，或希望围绕主题系统性扩展阅读时使用；第二类是概念级触发，适合某个概念掌握弱、解释不足或需要更多例子时使用；第三类是问题级触发，适合问答提示材料未覆盖、回答证据不足或用户追问需要补证时使用；第四类是高亮级触发，适合用户在阅读/观看过程中对某个片段产生延伸学习需求时使用。四类触发都进入同一条补料流水线，只是触发来源不同。

| 步骤 | 动作 | 说明 |
| --- | --- | --- |
| 1 | 记录触发来源 | 保存触发类型：主题 / 概念 / 问题 / 高亮，并记录对应 Topic、Concept、Question 或 Highlight。 |
| 2 | 生成检索意图 | 基于主题标题、已有材料摘要、概念说明或问题上下文生成查询词和筛选目标。 |
| 3 | 检索与抓取候选资料 | 调用本地检索 / 抓取链路获取网页或资料候选，提取标题、URL、正文片段和来源信息。 |
| 4 | 评估相关度与类型 | 为每条候选资料计算主题相关度，并判断资料类型是考试材料还是推荐阅读。 |
| 5 | 阈值过滤 | 只有主题相关度达到最低阈值的资料才会自动导入；低于阈值的候选只记录过滤原因。 |
| 6 | 自动导入并进入处理流水线 | 达标资料先创建或复用全局 `Material`，再创建当前 Topic 下的 `TopicMaterial` 关联；资料类型、主题相关度、导入理由、导入方式、导入时间都写在 `TopicMaterial` 上。随后进入摘要、正文清洗、chunk、概念候选和问答上下文构建流程。 |
| 7 | 人工治理 | 用户可在资料列表中查看导入理由、相关度和状态，并调整资料类型或删除资料。删除默认是将当前 `TopicMaterial` 标记为已删除，即从当前 Topic 移除，而不是全局删除 `Material`。 |
**重复资料处理：**自动补料导入前，系统需要按 URL、文件路径和标题相似度识别已有 `Material`。如果资料已存在，则复用全局 `Material`，只新增或更新当前 Topic 下的 `TopicMaterial`；如果同一 Topic 已经关联该资料，则不重复导入，只提示已存在，并按需要更新主题相关度、导入理由或状态；如果该关联此前已被用户删除，重新命中时默认提示「该资料此前已被移除」，允许用户手动恢复，不静默恢复。

### 补料失败态与完成提示

自动补料不是只设计成功链路。若检索无结果、候选抓取失败、正文过短、模型评估失败，或所有候选都低于最低相关度阈值，系统需要给出明确失败态，而不是静默结束。页面应提示无达标资料的原因，并允许用户查看被过滤候选、调整关键词、降低阈值或换一个主题 / 概念 / 问题重新触发。

**相关度与质量信号区分：**主题相关度只回答“这份资料和当前 Topic 是否相关”，不等于资料可信或质量高。V2-alpha 先不做独立可信度评分，但需要在资料记录中保留来源、摘要、推荐原因和抓取时间等质量信号，方便用户判断资料是否值得保留，也为后续扩展可信度 / 质量标签预留空间。

补料任务完成后采用轻量提示，不强打断当前学习流程。新增资料在资料列表中带「AI 新增」标识，并展示导入理由、相关度、分类和状态，方便用户稍后集中治理。

**「AI 新增」标识生命周期：**「AI 新增」是提醒用户进行后治理的临时状态，不应长期干扰列表。用户首次查看资料详情、调整分类或删除资料后，该标识消失；但「由 AI 推荐」作为导入方式 / 来源字段长期保留，用于后续追溯。

### 功能需求

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| S1 | 显式触发补料 | 入口包括主题页、概念卡片、问答「材料未覆盖」和高亮备注；触发时记录来源对象，后续推荐材料可追溯。材料空白状态归入主题级触发，不单独作为一类触发来源。 | P0 |
| S2 | 检索、抓取与语义筛选 | 系统根据触发上下文生成查询，调用检索与抓取工具获取候选材料，再由语义相似度和 LLM 判断进行筛选。 | P0 |
| S3 | 最低相关度阈值 | 每条候选材料必须得到 relevance_score；低于阈值不自动导入，仅记录为过滤结果。默认阈值可先固定，后续再开放为设置项。 | P0 |
| S4 | 自动分类与自动导入 | 达标材料自动导入，并由 AI 设置 material_category：考试材料或推荐阅读。AI 分类只是初始值，用户可改；默认判断标准是「能支撑用户理解主题核心内容 → 考试材料；只是主题相关的延伸内容，缺少也不影响理解主题本身 → 推荐阅读」。考试材料不是因为“适合出题”才被选中，而是因为它承载主题核心理解；进入复习 / 出题候选范围，是为了围绕核心内容做掌握度评估。推荐阅读优先作为延伸学习材料。 | P0 |
| S5 | 导入后材料治理 | 材料列表展示来源、相关度、分类、导入原因和「AI 新增」标识；用户可以调整类别、删除材料。删除默认仅将当前 Topic 下的 `TopicMaterial` 标记为已删除，该资料不再参与当前 Topic 的学习上下文，但不影响其他 Topic 复用同一份 `Material`。 | P0 |
| S6 | 补料记录与可追溯 | 记录触发来源、查询词、候选结果、过滤原因、导入材料、分类结果和人工调整记录，方便后续复盘推荐质量。 | P1 |

### 可行性评估

这个方案在当前技术栈下可行，且比原来的「推荐清单 + 人工确认」更贴近学习产品的节奏。后端主要在现有 `Material` / `Topic` / `AITask` 链路上引入 `TopicMaterial` 关联关系：`Material` 保存标题、状态、创建来源、媒体类型、媒体引用、原始内容、处理后内容、媒体元信息（含 md5）和摘要等全局字段；`TopicMaterial` 保存资料类型、主题相关度、导入理由、导入方式、导入时间和删除状态等 Topic 语境字段。SQLite 足够支撑本地单用户场景。前端用 React + Ant Design 可以直接实现分类标签、相关度展示、类别下拉、删除按钮、AI 新增标识和补料任务状态，不需要引入复杂组件。

主要风险在推荐质量，而不是工程实现。阈值过低会污染学习空间，阈值过高会漏掉有用材料；AI 自动分类也可能把拓展阅读误归到考试材料。为降低风险，V2-alpha 建议采用保守策略：只自动导入相关度达标材料；材料列表默认按类别分组展示；所有 AI 分类都允许人工调整；删除和改分类不破坏原始补料记录，便于后续复盘。

### 决策取舍

- **从入库前确认改为入库后治理。**原设计中用户通过勾选清单确认导入，控制感强但打断学习；新设计通过阈值过滤和可删除机制控制质量，把用户操作从「先审核」改为「后治理」。
- **材料分类直接影响后续学习行为。**考试材料默认进入出题、复习和掌握度评估候选；推荐阅读用于拓展理解，不默认进入考试范围，避免低结构化内容影响题目质量。
- **保留显式触发，不做无限后台推荐。**补料仍由用户在主题、概念、问题或高亮处触发，材料空白归入主题级触发，系统不主动持续抓取，避免噪声积累。
- **阈值先固定，后续再开放配置。**V2-alpha 可先使用默认最低相关度阈值，积累真实推荐数据后再决定是否开放给用户调整。
- **为什么不再保留逐条确认：**逐条确认会打断学习节奏；新设计用最低相关度阈值过滤低质材料，再允许用户在导入后改分类或删除，控制点后移但不消失。**代价：**需要把相关度、分类和推荐原因展示清楚。
- **为什么用本地 searxng + crawl4ai + Ollama，而不接商用搜索/大模型 API：**契合「数据不出本机」的定位，无 API 成本、无隐私外泄；对标 NotebookLM Discover 的联网广度我们会弱一截，但这不是本系统的立足点（见竞品分析）。**代价：**资料广度与抓取成功率不如云端，靠质量过滤兜底。
- **为什么补料必须绑定来源主题/问题/概念****：**这样补充材料可回答「它是围绕哪个主题、为解决哪个问题或概念而来的」，避免话题下散落一堆无归属链接。主题级补料直接绑定 Topic；概念/问题级补料再额外绑定触发对象。具体落库与关联方式以开发设计文档为准。

## 七、非功能性需求与范围边界

本系统跑在本机、只服务一个人，非功能性需求据此收敛，避免为不存在的场景过度设计：

| 维度 | 本版本取向 | 明确不做 |
| --- | --- | --- |
| 访问与安全 | 本机 localhost 访问即可 | 公网访问、登录鉴权、HTTPS |
| 多用户 | 单用户，无账号体系 | 多用户隔离、权限 |
| 数据与备份 | 本地 SQLite，数据不出本机 | 云端备份、同步 |
| 性能 | 面向单人本机数据量可用即可；视频转录/补料为异步任务，不阻塞交互 | 大规模并发/性能优化 |
| 前端适配 | 同一套 React Web 前端支持电脑与手机浏览器；桌面端采用宽屏高信息密度布局，手机端采用单栏触控布局 | 独立移动 App、第二套移动前端 |

## 八、阶段划分与里程碑

本版本按用户可感知的产品闭环分三阶段推进：先把本地视频学习跑通，再把自动补料接入学习过程，最后做整体体验收口。底层数据模型与迁移策略不在本文展开，统一以开发设计文档为准。

| 阶段 | 重点 | 交付与验收要点 | 优先级 |
| --- | --- | --- | --- |
| 阶段 1视频学习闭环 | 本地视频导入 + 字幕/Whisper ASR + 时间戳绑定 + 播放器三动作交互 | 本地视频可完整学习：概念、高亮、问答绑定时间点并可回跳；产出进入话题学习闭环 | P0 |
| 阶段 2自动补料闭环 | searxng + crawl4ai + Ollama 检索抓取过滤 + 相关度阈值 + 自动分类导入 + 绑定来源入库 | 用户从主题、概念、问题或高亮显式触发补料后，系统只自动导入相关度达标材料，并分类为考试材料或推荐阅读；材料保留来源标注并绑定触发主题/概念/问题/高亮 | P0 |
| 阶段 3体验收口 | 补料质量标注、视频与文本混合学习体验、整体验收。这里的补料质量标注不是新增评分体系，而是记录用户对 AI 推荐资料的治理行为，例如保留、删除、改分类，用于后续复盘推荐质量。 | 视频学习与自动补料能在同一话题下顺畅串联；用户能从材料、概念、问答、高亮回到对应学习位置 | P1 |

## 九、已确认决策、验收补充与后续规划

**已确认决策（本文据此设计）：**

- ✅ 视频：系统只支持导入本地视频文件，不处理任何外部链接或平台鉴权；无字幕时系统自动调 Whisper ASR 生成转写。
- ✅ 自动补料：显式触发后自动检索、过滤、分类并导入达标材料；材料分为考试材料和推荐阅读，用户可改分类或删除。
- ✅ 产品文档范围：本文不展开数据模型与迁移策略；相关内容统一维护在开发设计文档。
- ✅ 响应式：电脑与手机浏览器完整覆盖同一套功能；按屏幕和输入方式提供双布局，不简单缩放桌面页面。
- ✅ 范围边界：不做公网访问、鉴权、多用户、HTTPS、云端备份、大规模性能优化。

**开放问题（待实现阶段进一步定）：**

- 📌 Whisper ASR 的部署形态与模型规格（本地模型大小 vs 转写速度）在视频学习落地时确认。
- 📌 searxng 检索源配置与 crawl4ai 抓取失败的兜底策略在自动补料落地时确认。

### 验收补充清单

- 同一份 `Material` 关联两个 Topic 后，在其中一个 Topic 下删除资料，只标记该 Topic 的 `TopicMaterial` 为已删除，不影响另一个 Topic 继续使用该 `Material`。
- 阅读页标注默认仅展示当前 Topic 下创建的标注，用户可以切换为显示全部标注。
- 用户选中 Chunk 中间的部分文字后创建标注，点击该标注时跳转到该 Chunk 的起始时间，而不是词级时间点。
- 自动补料没有达标资料时，页面展示无结果原因，并允许查看被过滤候选。

### 后续规划

**浏览器插件方向：**后续可以考虑让用户直接在视频原站观看视频，由浏览器插件提供转录、标注和时间点绑定能力。理想体验是：用户在原站视频页面中看到转录稿，选中内容后可高亮、标记概念或发起问答；之后点击标注时，直接跳转到原视频对应时间点。

V2-alpha 暂不考虑这个方向。核心原因是视频音频获取或可访问音频流的问题绕不过去，不同平台的播放器结构、鉴权、字幕、反爬和页面变化差异很大，多平台适配和长期维护成本都会显著高于本地文件导入。当前版本先把本地视频导入、转录、Chunk 级时间定位、标注回跳和学习闭环跑稳定；等这条核心链路稳定后，再评估是否扩展到浏览器插件。
