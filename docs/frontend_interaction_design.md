# 前端交互关键设计

本文记录当前前端不可随意回退的交互行为，以及后续页面必须遵循的设计标准。具体组件实现以代码为准；修改现有交互前，应先确认本文记录的用户意图是否仍成立。

## 1. “简洁高效”的含义

简洁不是减少能力，而是降低用户找到信息、完成操作和回到学习上下文的成本。

1. **内容优先**：学习页面把主要空间留给正文、字幕、学习产出和对话，不让设置项、状态字段或重复入口抢占视线。
2. **渐进展示**：常用主操作直接可见；编辑表单、设置项、详细元数据和低频操作放入 Modal、Drawer、Popover、Tab 或行内展开。
3. **上下文连续**：使用 SPA 跳转，不因页面切换刷新应用；从学习产出、讨论或管理页进入原文后，必须能回到明确的 Topic，并保留定位语境。
4. **操作就近**：状态、进度、错误和重试入口应出现在触发操作的页面或条目附近，不能只依赖全局 Toast 或任务管理页。
5. **复杂信息使用合适载体**：学习入口用卡片，学习产出用分组列表，管理型数据用表格和行内展开，对话与上下文工具用侧边抽屉。
6. **紧凑但不拥挤**：次要操作优先使用图标按钮，并提供 `title`、Tooltip 或 `aria-label`；正文与长文本保持足够行高、间距和可读宽度。
7. **关键操作始终可达**：长页面中的返回、学习工作区、阅读设置、对话输入和任务进度应通过 sticky 或固定工具区保持可见，但不能遮挡正文。

以下做法不符合“简洁高效”：

- 为同一能力在页面多个位置放置重复入口。
- 为减少一次点击，把所有表单、详情和设置永久铺开。
- 只显示内部枚举 Key、任务 ID 或原始 JSON，让用户自行解释状态。
- 用 Toast 代替持续任务状态、错误原因或重试入口。
- 在浅色主题中用大面积深色块展示长文本或代码上下文。
- 通过删除 V1 已有能力来换取表面简洁。

## 2. 全局信息架构

全局 Header 保持精简并固定在顶部：

- 点击产品标题返回 Topic 列表。
- 一级入口只保留材料管理、任务管理、复习计划和系统设置。
- 全站背景通过图标 Popover 快速切换，不单独占用页面。

主要页面职责：

| 页面 | 交互职责 |
| --- | --- |
| Topic 列表 | 创建、搜索和进入学习话题。 |
| Topic 详情 | 展示学习目标、学习产出、材料及 Topic 级操作。 |
| 阅读页 | 阅读正文/视频、划词标注、问答和回跳。 |
| 概念图 | 查看概念关系并编辑节点/连线。 |
| 材料管理 | 全局检索、筛选、关联、诊断和删除材料。 |
| 任务管理 | 查看异步任务上下文、结果、错误和执行重试。 |
| 评估/复习 | 完成掌握度评估与间隔复习闭环。 |
| 系统设置 | 管理服务、模型路由和界面默认值。 |

页面间跳转统一使用 `useNavigate` 或 React Router `Link`，避免 `window.location` 造成整页刷新。

## 3. Topic 学习入口

### Topic 列表

- 桌面端每行固定四张等宽卡片；内容长短不能改变卡片宽度和高度。
- 卡片只展示标题、两行学习目标、材料数和本地化掌握度，长文本省略并通过 Tooltip 查看全文。
- 点击整张卡片进入 Topic；删除按钮阻止卡片点击，并必须二次确认。
- 搜索只占一行，不为单一筛选建立复杂筛选面板。
- 新建 Topic 使用 Modal，可选择暂不添加材料，也可同时添加网页或文本作为初始材料。

### Topic 详情

页面信息顺序保持为：

1. 返回 Topic 列表。
2. Topic 标题、目标、范围、状态和核心操作。
3. 学习产出。
4. 学习材料。

关键行为：

- 标题旁使用紧凑编辑图标；编辑标题、目标和范围放在 Modal 中。
- Topic 级高频操作集中在标题区：学习讨论、查找材料、概念图、掌握度评估。
- 学习产出使用“概念 / 问答 / 高亮”三个 Tab，不把三类长列表同时铺开。
- 学习产出统一采用“主体内容 + 原文引用 + 结论/备注”的阅读结构；原文引用明确标出材料来源。
- 每条学习产出就近提供回原文、编辑、补料、确认或删除；删除必须确认。
- 材料列表区分 AI 推荐与人工添加，展示本地化处理状态；解除关联只影响当前 Topic。
- 添加材料统一通过一个 Modal，在网页、文本、视频和已有材料之间切换，不在页面放置多个上传入口。

## 4. 阅读页

阅读页是核心体验，任何新功能都不能显著压缩正文空间或打断连续阅读。

### 页面框架

- 顶部使用 sticky 工具栏，明确显示 `返回主题：《主题名》`，并展示当前材料的概念、问答和高亮数量。
- 学习产出入口统一为“学习工作区”，不再增加重复的悬浮入口。
- 材料摘要默认折叠，用户需要时再展开。
- 加载时展示 Skeleton；材料不可用时展示原因、返回和重新加载；材料处理中显示当前本地化状态。
- AI 任务在阅读页内展示排队/执行/成功/失败，失败时显示错误和重试按钮。

### 正文与视频

- 文本和网页正文使用 `react-markdown + remark-gfm`，支持标题、列表、引用、链接、代码和表格，同时保留 Markdown 源码 offset 与 Locator 的映射。
- 视频采用“播放器 + 转录稿”工作区。宽屏约按 `3:2` 双栏，播放器 sticky；窄屏恢复上下布局。
- 字幕随播放时间高亮并自动滚动；点击字幕 seek 到对应时间。
- 视频时间戳只用于展示，不参与正文 offset。
- 视频学习标记当前显示在播放器下方并可点击 seek；后续还需绘制到播放器进度条。

### 划词与标注

- 用户选中文字后，在选区附近显示紧凑菜单：标记概念、发起问答、高亮。
- 选区菜单必须避让视口边缘；取消选区、滚动正文或按 `Escape` 时立即关闭。
- 点击正文中的既有标注，打开学习工作区并切换到对应 Tab；问题标注同时进入对应对话。
- 点击工作区中的概念或高亮，回跳原文；视频材料 seek 到时间，文本材料滚动到 offset。
- 连续点击同一条目标注仍必须重新触发跳转和临时高亮，不能因参数未变化而失效。

### 阅读设置与朗读

- 朗读播放键是独立主按钮；背景、字体、音色和倍速收进右侧紧凑工具坞。
- 工具坞用色块、字体简称、音色简称和倍速展示当前值，避免宽文字按钮占用正文。
- 全站背景与阅读背景共享状态并持久化；阅读字体独立持久化。
- 正文、字幕和阅读型内容继承选中字体；代码保持等宽字体。
- 文本朗读使用后端 TTS 音频，支持播放/暂停、双击停止、音色切换、`0.5x` 至 `3x` 倍速和当前段落高亮。
- 视频材料使用原始音轨，禁用不适用的 TTS 控件并说明原因。

### 学习工作区

- 使用右侧 Drawer，不离开正文页面。
- 通过 Tab 平铺问答、概念和高亮，Tab 标签显示数量。
- 列表项整行可点击：问答进入对话，概念和高亮回原文；行内图标处理编辑、补料、确认和删除。
- 空状态必须告诉用户下一步，例如“选中原文后标记第一个概念”。
- 新问题输入与历史对话输入严格分开，避免把新问题误发到旧 Session。
- 问答对话顶部固定展示最初引用的原文，并提供“回原文”。
- 用户和 AI 消息均渲染 Markdown/GFM；发送后滚动到最新消息。
- AI 回复期间展示“排队中/正在回复”，禁用输入和重复提交；刷新页面后应恢复任务状态。

## 5. Topic 讨论与补料

- Topic 讨论使用右侧 Drawer，让用户在 Topic 页面内继续学习，不跳转到独立聊天页。
- 对话输入固定在抽屉底部；`Enter` 发送，`Shift+Enter` 换行。
- 用户与 AI 消息使用不同但主题兼容的背景，AI 消息完整渲染 Markdown/GFM。
- 回复任务进行中禁用重复发送，并显示排队或使用中的模型状态。
- 补料进度固定在抽屉顶部，持续展示阶段、候选数、已处理数和推荐数；出现首个候选不代表任务结束。
- 候选材料以结构化卡片展示标题、摘要、相关度、分类、理由和原文入口。
- 候选只能由用户采纳或忽略；采纳后才关联 Topic 并进入处理流水线。

## 6. 管理、评估与复习

### 材料与任务管理

- 复杂管理数据使用表格，不退回信息密度低且难比较的卡片墙。
- 表格首屏只展示用于判断和操作的字段；媒体元信息、完整正文、错误和关联详情放在行内展开。
- 材料处理进度用紧凑状态标记展示“原/清/摘”和各 TTS 音色状态，失败原因通过 Tooltip 或展开区查看。
- 搜索、状态筛选和 Topic 筛选保持在同一行；支持“未关联任何话题”这一治理视角。
- 行内操作优先用图标；重新导入、全局删除和关联 Topic 均在当前行完成。
- 任务管理支持状态/类型筛选；完整上下文、输入、结果和错误放在展开区，失败/取消任务提供重试。

### 评估与复习

- 评估页在同一页面完成生成、作答、草稿保存、提交评分和历史查看。
- 出题/评分任务必须显示页面内状态，刷新后恢复，失败后可重试。
- 已评分结果不仅显示总分，还要展示逐题回答、得分和反馈。
- 复习列表按记录展示提示、反馈、得分和下次复习时间；提示和评分任务按记录独立反馈。
- 复习提示使用 Markdown/GFM；提交复盘使用 Modal，避免在列表中永久展开长表单。

## 7. 文案与视觉规则

### 用户可见文案

- 使用中文描述性文本，不直接展示 `pending`、`exam_material`、`web_page` 等内部 Key；发现现存例外应作为缺陷修复，不能作为新实现范例。
- 状态文案说明“正在发生什么”和“用户下一步能做什么”，避免只有“处理中”或“失败”。
- 空状态应给出行动提示；错误状态应给出原因和重试入口。
- 危险操作必须说明影响范围，例如“只移除当前 Topic 关联”或“同时删除媒体文件”。

### 长文本与 Markdown

- 正文和 AI 长文本行高原则上不低于 `1.6`，控制行宽、段落间距和列表缩进。
- Markdown 容器不得使用 `white-space: pre-wrap`；否则段落和列表会产生异常空白。
- 表格允许横向滚动；代码块允许内部滚动，不能撑破页面。
- 浅色主题下不得使用大面积黑色背景承载长文本、JSON 或完整上下文。
- 长标题、目标和摘要在列表中省略，并通过 Tooltip、展开区或详情页提供完整内容。

### 主题与字体

- 所有页面跟随统一的全站背景；暗色背景同步启用 Ant Design dark algorithm。
- 颜色优先使用 Ant Design token 或随主题变化的颜色，不写死只适合单一主题的前景/背景组合。
- 当前支持纯白、暖黄、护眼绿、柔灰、深黑、夜蓝、炭灰和暖黑；新增页面必须在明暗主题下都可读。
- 当前支持系统字体、宋体、楷体和衬线字体；新增阅读型内容必须继承阅读字体。

## 8. 状态与安全交互

所有异步页面至少覆盖以下状态：

1. 首次加载：Skeleton、Spin 或明确加载文案。
2. 空数据：说明当前为空及下一步操作。
3. 排队/执行：持续可见，必要时展示阶段或进度。
4. 成功：刷新业务数据，避免用户手动刷新页面。
5. 失败：展示可读错误和原地重试。
6. 刷新恢复：重新进入页面后能从 AITask 恢复未完成或失败状态。

交互约束：

- 任务执行期间禁用会产生重复任务的按钮和输入。
- 删除 Topic、Material、概念、问答、高亮和关系必须确认。
- 图标按钮必须具备可访问名称。
- 键盘输入场景支持 `Cmd/Ctrl+A` 全选；对话中明确区分发送与换行。
- 页面跳转、Drawer 开关和 Tab 切换不能悄悄丢失已提交的数据。

## 9. 实现原则

- 优先复用 Ant Design、Vidstack、React Markdown 等稳定开源组件，不自研已有成熟能力。
- 新交互应复用现有页面模式和主题机制，避免创建另一套 Drawer、状态提示、Markdown 或颜色系统。
- 结构化数据使用组件和结构化 API，不通过字符串拼接模拟表格、状态机或富文本。
- 紧凑布局不能以牺牲可访问性、错误反馈或完整能力为代价。
- 新功能若改变上述关键行为，应同步更新本文和 handoff，并说明为什么原决策不再适用。

## 10. 变更检查清单

提交前至少确认：

- 是否减少了正文或核心信息的可用空间？
- 是否新增了重复入口或不必要的页面层级？
- 是否在触发位置展示任务进度、失败原因和重试？
- 刷新页面后，异步状态是否仍可恢复？
- 是否展示了内部 Key，而不是本地化文本？
- 长文本、Markdown、代码和表格是否在明暗主题下可读？
- 阅读字体和全站背景是否正确继承？
- 图标按钮是否有 Tooltip、`title` 或 `aria-label`？
- 删除和全局影响操作是否明确说明范围并二次确认？
- 从学习产出或标注跳转后，能否回到正确原文和 Topic？
- 文本 offset、视频 seek、字幕时间戳和标注点击是否仍一致？
