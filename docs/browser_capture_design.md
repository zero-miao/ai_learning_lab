# 浏览器页面采集设计

## 1. 结论

反馈 #42“支持导入飞书文档”和 #43“登录后从浏览器页面抓取内容”应合并为一个通用能力：**采集当前页面**。

- #43 定义通用能力：采集浏览器中已经渲染、用户当前能看到的页面。
- #42 是首个重点适配和验收场景，不单独建设一套飞书导入链路。
- 公开网页仍可使用现有“输入链接”导入；登录态、动态渲染和复杂文档优先使用浏览器采集。
- 系统纯本地运行，扩展直接连接 `127.0.0.1`，不引入账号、配对码或设备授权流程。

核心目标按优先级排序：

1. 用户只需一次安装，之后一键采集。
2. 同一套能力适用于文章、知识库、在线文档、论坛帖子和登录后页面。
3. 自动模式覆盖大多数页面，复杂页面允许用户切换采集方式。
4. 采集失败时给出可理解的预览和修正入口，不要求用户理解 DOM 或抓取规则。

## 2. 产品形态

采用 Manifest V3 浏览器扩展，直接读取当前标签页已经渲染的内容。

扩展安装后自动探测本机服务：

1. 默认连接 `http://127.0.0.1:8000`。
2. 探测失败时允许设置一次服务地址和端口，之后自动记忆。
3. AI Learning Lab 的材料导入界面显示扩展是否在线，并提供安装和连接指引。

项目构建时直接产出可加载的扩展目录和压缩包。应用内“安装浏览器采集器”页面只保留一次性流程：

1. 下载或定位扩展目录。
2. 打开浏览器扩展管理页并加载。
3. 返回应用后自动完成连通性检测。

扩展预先声明所有网页和本地服务权限。安装完成后不再逐站申请权限，不要求输入配对码，也不要求在扩展和应用之间复制配置。

不采用以下方案：

- **后端 Playwright**：需要额外浏览器窗口和独立登录，无法复用用户正在阅读的页面，操作割裂。
- **书签脚本**：受站点 CSP、跨域和脚本长度影响，复杂文档和图片不稳定。
- **飞书专用 API 优先**：只能解决单一站点，配置成本高，也无法覆盖其他登录态页面。

## 3. 最短操作路径

扩展弹窗默认只展示三个信息：

- 当前页面标题。
- 采集目标：上次使用的 Topic 或“稍后整理”收件箱。
- 主操作“采集当前页”。

一次标准采集流程：

1. 用户在目标页面点击扩展图标。
2. 扩展自动判断页面类型并选择采集模式。
3. 用户点击“采集当前页”。
4. 弹窗显示正文块数、图片进度和失败项数量。
5. 完成后默认自动打开 AI Learning Lab 预览页。
6. 用户选择 Topic，并执行“直接导入”或“保存为草稿”。

为了支持连续收集资料，扩展还提供“采集后留在当前页”。多篇内容先进入采集收件箱，用户之后统一归类，不要求每次采集都切回应用。

## 4. 用户可选的采集模式

默认使用“自动”，同时保留四种明确模式：

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| 自动 | 绝大多数页面 | 根据页面结构选择文章、文档或选区模式 |
| 文章正文 | 新闻、博客、论坛长帖 | 去除导航、推荐、评论和侧栏 |
| 完整文档 | 飞书、Notion、语雀、在线知识库 | 保留块顺序、标题、表格、代码和图片，并处理长文滚动 |
| 选中内容 | 页面只需保留一部分 | 只采集当前浏览器选区 |
| 整页可见内容 | 自动提取不完整时兜底 | 按页面视觉顺序保留主要可见文本与媒体 |

扩展记住同一域名上次成功使用的模式。用户不需要每次重新选择。

浏览器右键菜单提供“将选中内容采集到 AI Learning Lab”，用于快速保存段落、答案或局部表格。

## 5. 通用文档快照

扩展不直接把站点 DOM 当作最终材料，也不让每个站点分别生成 Markdown。所有采集器先输出统一的 `DocumentSnapshot`：

```json
{
  "title": "文档标题",
  "source_url": "https://example.com/document",
  "site_name": "Example",
  "captured_at": "2026-08-15T12:00:00",
  "adapter": "generic-document",
  "blocks": [
    {"id": "b1", "type": "heading", "level": 1, "text": "第一章"},
    {"id": "b2", "type": "paragraph", "spans": [{"text": "正文"}]},
    {"id": "b3", "type": "image", "asset_id": "sha256:...", "alt": "架构图"}
  ],
  "assets": [
    {
      "id": "sha256:...",
      "source_url": "https://example.com/image.png",
      "content_type": "image/png",
      "size": 123456
    }
  ],
  "warnings": []
}
```

基础块类型包括：

- heading
- paragraph
- ordered_list / unordered_list
- quote
- code
- table
- image
- link_card
- divider
- attachment

统一快照带来三个好处：

1. 通用采集器和飞书适配器可以复用同一套预览、Markdown 转换和测试。
2. 后续增加 Notion、语雀等适配器时不修改后端材料契约。
3. Markdown 转换失败时仍保留原始结构快照，可改进转换器后重新生成。

## 6. 适配器体系

扩展内置一个按评分选择的适配器注册表：

```ts
interface CaptureAdapter {
  id: string;
  score(context: PageContext): number;
  collect(context: PageContext): Promise<DocumentSnapshot>;
}
```

适配器优先级：

1. 用户选区适配器。
2. 站点专项适配器，例如飞书。
3. 通用结构化文档适配器。
4. Readability 文章适配器。
5. 整页可见内容兜底适配器。

自动模式并非只选择最高分结果。采集后会做质量检查：

- 正文是否过短。
- 标题是否存在。
- 文本是否大量重复。
- 页面可见图片和采集图片数量是否明显不一致。
- 是否只采集到导航、目录或加载提示。

质量不足时，弹窗直接建议另一种模式，例如“自动模式只获取到 3 个段落，建议改用完整文档”。

## 7. 长文档与虚拟滚动

在线文档常只在 DOM 中保留当前视口附近的块。只读取一次 DOM 会漏掉未滚动区域，因此“完整文档”模式必须支持滚动采集：

1. 自动识别主滚动容器，而不是固定滚动 `window`。
2. 记录当前位置，从顶部开始分段滚动。
3. 每次等待内容稳定后采集当前块。
4. 优先使用站点块 ID 去重；没有块 ID 时使用结构、文本和相邻块生成指纹。
5. 连续两次滚动没有新增块或到达底部时结束。
6. 完成或取消后恢复用户原滚动位置。

弹窗持续显示“已采集 126 个块，正在读取第 8/12 屏”，并允许随时取消。

通用滚动采集器解决大部分虚拟列表；飞书适配器只负责更准确地识别文档容器、块 ID 和特殊块结构。

## 8. 图片和媒体

图片采集按以下顺序处理：

1. 读取 `currentSrc`、`srcset`、常见懒加载属性和图片说明。
2. 在当前页面上下文中下载图片，因此可以复用页面已有登录状态。
3. 支持普通 URL、Blob URL 和 Data URL。
4. 同一内容按 SHA-256 去重，但保留图片在正文中每次出现时不同的说明文字。
5. 无法直接读取时，允许对单个图片元素进行截图作为兜底。

正文使用 `asset://<id>` 引用资源。后端落盘后统一改写为本地 `/media/` 地址，复用反馈 #40 已实现的本地图片生命周期。

默认资源上限用于避免误采集整站素材，不作为安全策略：

- 最多 100 张正文图片。
- 单张默认 20 MB。
- 单篇材料默认 200 MB。

达到上限时暂停并让用户选择“继续全部采集”或“只保留已采集内容”，不直接失败。

首版保留图片，不处理视频下载。页面中的视频转成带标题的来源链接；后续可单独接入现有视频材料流程。

## 9. 特殊页面的通用处理

### PDF

- 浏览器地址是可下载 PDF 时，扩展直接下载文件并交给现有 AnyDoc 流程。
- 登录后才能访问的 PDF 由扩展在当前会话中下载，再上传本地处理。

### iframe

- 同源 iframe 递归采集。
- 跨域 iframe 在用户进入该 iframe 页面后单独采集；预览中标记未合并的嵌入区域。

### Shadow DOM

- 通用遍历器递归读取开放的 Shadow Root。
- 封闭 Shadow Root 无法读取时回退到可见文本或选区采集。

### Canvas 和画板

- 先保存画布截图和附近说明文字。
- 不在首版尝试恢复可编辑图形结构。

## 10. 本地接收与预览

后端只需要一个暂存模型 `CapturedDocument`：

- `title`
- `source_url`
- `site_name`
- `adapter`
- `snapshot_json`
- `markdown`
- `asset_manifest`
- `warnings`
- `status`: `receiving / ready / imported / failed`
- `created_at`
- `updated_at`

扩展通过一个本地 API 提交快照和资源：

- `POST /api/browser-captures/`：创建采集记录并上传快照。
- `PUT /api/browser-captures/{id}/assets/{asset_id}/`：上传资源，可并发和重试。
- `POST /api/browser-captures/{id}/complete/`：完成采集并生成 Markdown 预览。
- `POST /api/browser-captures/{id}/import/`：选择 Topic 后直接创建正式材料。
- `POST /api/browser-captures/{id}/create-draft/`：创建可继续编辑的 `MaterialDraft`。
- `DELETE /api/browser-captures/{id}/`：从收件箱删除。

预览页采用双栏：

- 左侧为最终阅读效果。
- 右侧为大纲、资源清单和告警。

用户可在预览页：

- 修改标题。
- 删除错误段落或图片。
- 切换另一种采集模式并覆盖当前结果。
- 选择 Topic。
- 直接导入或进入 Markdown 草稿继续编辑。

采集收件箱按时间倒序展示来源、标题、块数、图片数和目标 Topic，支持批量删除和批量归类。

## 11. 草稿与资源生命周期

采集结果在用户确认前由 `CapturedDocument` 持有正文和图片。

- “直接导入”：复制资源到 Material 目录，改写 Markdown 地址，创建 Material 和 TopicMaterial，再进入摘要/TTS 流程。
- “保存为草稿”：MaterialDraft 记录来源 capture，正文继续引用 capture 资源。
- 草稿发布：把 capture 资源转移到 Material 目录，并同步改写当前正文和历史版本中的资源地址。
- 草稿删除：若没有其他引用，一并删除 capture 和资源。
- 收件箱删除：没有草稿或材料引用时立即清理资源。

这样既保留现有草稿编辑和版本能力，也不会要求扩展理解 Material、TopicMaterial 或 AITask。

## 12. 飞书专项适配

飞书适配器只负责把飞书页面转换成通用块，不建立另一条导入链路。

首版支持：

- 文档标题和完整块顺序。
- 标题、段落、列表、引用、待办事项。
- 表格和代码块。
- 图片及图片说明。
- 超长文档虚拟滚动。
- 文档内普通超链接。

首版降级处理：

- 画板、流程图：截图。
- 多维表格：当前可见区域转表格或截图。
- 文件附件：保留名称和下载链接。
- 评论、历史版本和协作者信息：不采集。

若飞书 DOM 改版，只需更新飞书适配器和固定页面样本，不影响快照、预览、草稿和材料流程。

## 13. 实施顺序

### 第一阶段：通用可用版本

1. 扩展自动连接本地服务。
2. 自动、文章正文、选中内容三种模式。
3. DocumentSnapshot、Markdown 转换和图片上传。
4. 采集收件箱、预览、直接导入和创建草稿。
5. Chrome 真实页面端到端测试。

### 第二阶段：复杂文档

1. 完整文档模式和通用虚拟滚动采集器。
2. 飞书适配器。
3. 表格、代码块、登录态图片和长文专项验收。
4. 模式质量诊断和自动降级建议。

### 第三阶段：扩大通用性

1. 根据真实失败样本增加 Notion、语雀等轻量适配器。
2. PDF 登录态下载、iframe、Shadow DOM 和 Canvas 兜底。
3. 批量采集和批量归类。

不预先建设大量站点规则。只有通用适配器出现可重复失败样本时，才增加站点适配器。

## 14. 验收标准

通用能力：

- 安装扩展后无需再次配置即可采集。
- 普通文章从点击到进入预览不超过三个操作。
- 选区、文章、结构化文档都进入同一收件箱和预览流程。
- 长文滚动采集不会漏掉明显章节，也不会大量重复。
- 失败时能明确切换模式或保留部分结果。

飞书场景：

- 登录后单篇文档可一键采集。
- 标题层级、列表、表格、代码和图片顺序正确。
- 长文档采集完成后恢复原阅读位置。
- 图片本地加载，刷新和断网后仍可查看。
- 用户可直接导入，也可进入现有 Markdown 草稿继续编辑。
